# minga-arena

**Когда Claude раз за разом даёт слабый ответ, устройте турнир: 16 субагентов получают одну и ту же задачу и разные карты стратегии, атакуют работы друг друга, защищаются и исправляют свои, а судья оценивает каждый матч, пока не останется один ответ.**

Часть экосистемы [Minga](https://github.com/dmminga1983/minga). Рассчитан на обычную подписку: по умолчанию 16 агентов, с `--quick` 8, а 100 только по вашему запросу. У каждой роли своя модель: судьи сильные, атаки дешёвые. Бесплатно, MIT, без API-ключей, ничего подключать не нужно.

[English version →](README.md)

## Как это работает

1. **Старт.** N субагентов получают одинаковую задачу, байт в байт (это проверяет тест), и каждый свою карту: способ мышления (15), порядок работы (12) и приоритет (12 плюс свои у домена). Это больше 2000 разных карт. Раздающий не повторяет карты, распределяет все части поровну, а на небольших запусках не даёт двум агентам совпасть даже по двум частям карты.
2. **Атака.** Агенты разбиваются на пары так, чтобы в паре не было одинакового способа мышления. Каждый атакует решение соперника через свою карту: до 7 атак с пометками FATAL, MAJOR или MINOR, каждая с точным местом и конкретным контрпримером.
3. **Защита.** Каждый признаёт или опровергает каждую атаку и переписывает своё решение с исправлениями.
4. **Судья.** Отдельный судья читает оба исправленных решения, сам проверяет каждую атаку и ставит баллы по критериям домена. Карт он не видит. Арифметику делает `arena.py`: проходит тот, у кого выше взвешенная сумма, а решение с подтверждённой фатальной ошибкой не может выиграть у решения без неё.
5. **Повтор**, пока не останется один. При нечётном числе кто-то проходит без матча, но один и тот же агент дважды не проходит, пока другие ждут своей очереди.
6. **Финальная проверка.** Если вы начали с ответа, который не понравился, последний судья вслепую сравнивает с ним победителя. Счёт вы увидите, даже если старый ответ выиграл.

Основная сессия не читает сотни файлов: каждый субагент пишет результат на диск и отвечает одной строкой, а весь турнир хранится в одном JSON-файле. Если посреди турнира разговор сожмётся, `arena.py next` продолжит с того же места.

## Установка

**Claude Code**, как плагин:

```
/plugin marketplace add dmminga1983/minga-arena
/plugin install minga-arena@minga-arena
```

Или скопируйте папку, чтобы получить просто `/minga-arena`:

```bash
git clone https://github.com/dmminga1983/minga-arena.git
cp -r minga-arena/skills/minga-arena ~/.claude/skills/
```

Нужен Claude Code (навык запускает субагентов через инструмент Agent) и Python 3.8 или новее. Ставить через pip ничего не нужно.

## Как пользоваться

```
/minga-arena
/minga-arena --quick придумай заголовок для страницы цен
/minga-arena --domain code почини нестабильный тест в tests/test_api.py
/minga-arena --domain legal составь досудебную претензию по этим документам
/minga-arena --agents 32 --budget max распиши план запуска на неделю
```

Без аргументов `/minga-arena` берёт ваш последний запрос как задачу, а ответ, который вам не понравился, как планку, которую надо побить. Claude может запустить навык и сам, если вы скажете «плохой ответ, устрой им битву», но тогда сначала спросит, прежде чем тратить лимит.

| флаг | что делает |
| --- | --- |
| (без флага) | 16 агентов |
| `--quick` | 8 агентов |
| `--agents N` | любое число |
| `--full` | 100 агентов |
| `--domain D` | критерии и дополнительные карты: `general`, `code`, `writing`, `legal`, `expertise` |
| `--budget B` | какая модель играет какую роль: `economy`, `balanced`, `max` |
| `--seed S` | тот же seed даёт те же карты и ту же сетку |
| `--wave W` | субагентов в одной волне, по умолчанию 10 |

## Сколько стоит

Навык бесплатный, а вызовы идут из лимита вашей подписки. Поэтому перед стартом он показывает размер турнира и просит подтверждения, если агентов больше 32 или выбран `--budget max`.

| агентов | раундов | вызовов субагентов |
| --- | --- | --- |
| 8, `--quick` | 3 | 43 |
| 16, по умолчанию | 4 | 91 |
| 32 | 5 | 187 |
| 100, `--full` | 7 | 595 |

| бюджет | участники | атакующие | защищающиеся | судьи |
| --- | --- | --- | --- | --- |
| `economy` | haiku | haiku | haiku | sonnet |
| `balanced` (по умолчанию) | sonnet | haiku | sonnet | sonnet |
| `max` | sonnet | sonnet | sonnet | opus |

`python3 skills/minga-arena/arena.py plan --agents N --budget B` в любой момент покажет число вызовов по моделям.

## Домены

Каждый домен лежит отдельным JSON-файлом в `skills/minga-arena/domains/`: критерии, их веса (в сумме ровно 100), опорные оценки и дополнительные карты приоритетов. Их можно править или добавлять свои.

| домен | что оценивает судья |
| --- | --- |
| `general` | правильность 30, полнота 25, устойчивость к атакам 20, конкретность 15, ясность 10 |
| `code` | правильность 35, проверяемость 20, полнота 20, безопасность 15, ясность 10 |
| `writing` | попадание в аудиторию 25, конкретность 20, живой голос 20, правдивость 20, структура 15 |
| `legal` | правовое основание 30, доказательства 25, конкретные требования 20, полнота 15, ясность 10 |
| `expertise` | цепочка ФАКТ, ДОКАЗАТЕЛЬСТВО, НОРМА, ВЫВОД 30, нормы 25, причинность 20, объективность 15, ясность 10 |

## Инструмент

`arena.py` написан на чистом Python без зависимостей. Благодаря ему оркестратор не сбивается со счёта.

```bash
python3 arena.py plan --agents 16              # раунды, вызовы, вызовы по моделям
python3 arena.py init --task-file task.md --quick --domain writing [--baseline-file old.md]
python3 arena.py next                          # что делать дальше, с точной командой
python3 arena.py prompts attack                # написать брифы, вывести задания волнами с моделями
python3 arena.py check judge                   # каких результатов ещё нет
python3 arena.py collect                       # записать вердикты судей
python3 arena.py advance                       # выбыли проигравшие, пары для следующего раунда
python3 arena.py status | winner | domains
```

Тесты прогоняют полные турниры от 1 до 100 агентов с подставными субагентами, каждый домен, финальную проверку, повтор пропавших результатов, гарантии раздачи карт и правила решения матчей:

```bash
python3 -m unittest discover -s tests -v
```

## Важные оговорки

- **«16 версий Claude» это 16 субагентов**, а не 16 разных моделей. Разными их делает карта.
- **«Лучший ответ» значит тот, что пережил все матчи.** Судьи тоже Claude и оценивают по критериям, которые вы можете прочитать и изменить. Это сильнейший ответ, который нашёл турнир, а не доказательство его правоты. Поэтому навык показывает, какие атаки ответ пережил, и честно говорит, если ваш старый ответ набрал больше.
- **Юридические документы и разборы экспертиз всё равно проверяет специалист**, прежде чем на них полагаться.
- **Навык не меняет ваш проект.** Код возвращается как diff или целые файлы, применять их или нет, решаете вы.
- **Субагенты не видят ваш чат.** Всё, что они знают, это файл задачи. Размытая задача даст 16 вариантов размытого ответа.
- **Ждите запросов разрешений**, если не включён режим автоматического принятия правок: каждый субагент пишет файл в `.arena/`.
